# Exec CGI — Documentation

`exec-cgi` runs a PHP script through `php-cgi` the way a web server would
for a `GET` request, without a web server. It takes the request as one
argument, `script?query`, and writes the response to the console or to a
file:

```
exec-cgi "page.php?lang=en&id=5" page.html
```

`page.php` sees `$_GET['lang'] == 'en'` and `$_GET['id'] == '5'`, as if
it had been requested as `http://localhost/page.php?lang=en&id=5`, and its
output lands in `page.html`.

It is a small command line tool. It is not a library: there is no API to
link against, only the `exec-cgi` executable (the C++ class behind it is
described in [Reference](reference.md) for people working on the tool
itself).

```
exec-cgi              <-- this tool
xyo-system            (IApplication, Shell::setenv, Shell::system, String)
xyo-encoding, xyo-multithreading, xyo-data-structures,
xyo-managed-memory, xyo-platform
php-cgi               (from a PHP installation, found on the PATH at run time)
```

## Why it exists

PHP has two command line programs, and neither runs a page with a query
string:

| Program | `php page.php?id=5` | Problem |
|---------|---------------------|---------|
| `php` (CLI) | looks for a file named `page.php?id=5` | no `$_GET`, no `$_SERVER['QUERY_STRING']`; arguments go to `$argv` instead |
| `php-cgi` | the same | reads the request from **environment variables** (CGI/1.1), which must be set by hand, and refuses to run at all without `REDIRECT_STATUS` |

`exec-cgi` sets those variables and starts `php-cgi`, so a page written for
a web server can be run from a script or a build:

| Need | What `exec-cgi` does |
|------|----------------------|
| Generate static `.html` files from `.php` templates at build time | `exec-cgi "page.php?lang=ro" page.ro.html`, once per page and parameter set |
| Run a page that reads `$_GET` without a web server | sets `QUERY_STRING`, `REQUEST_METHOD=GET` and the rest of the CGI environment |
| Test a page from the command line | prints the response, headers and body, on the console |
| Use it in a script | the exit code is the exit code of `php-cgi` |
| Same command on Windows and Linux | the command line is run through the system shell on both |

## Concepts at a glance

| Need | Command |
|------|---------|
| Run a page, print the response | `exec-cgi "page.php?a=1&b=2"` |
| Run a page, write the response to a file | `exec-cgi "page.php?a=1&b=2" page.html` |
| Run a page without parameters | `exec-cgi page.php [output]` |
| Version / help / license | `exec-cgi --version`, `--help`, `--usage`, `--license` |

Quote the request: `&` separates commands in every shell, and `?` is a
wildcard on Linux.

## What to know before using it

- **The response starts with HTTP headers** (`X-Powered-By`,
  `Content-type`, a blank line), then the page. `php-cgi` ignores `-q` when
  it runs as a CGI program, so the headers are always there, also in the
  output file. See [CGI environment](cgi-environment.md#output).
- **`php-cgi` must be on the `PATH`.** `exec-cgi` does not look for it
  anywhere else.
- **Only `GET`.** There is no way to send a `POST` body, cookies or request
  headers.
- **Not for untrusted input.** The script and output paths are put into a
  shell command line. See [CGI environment](cgi-environment.md#security).
